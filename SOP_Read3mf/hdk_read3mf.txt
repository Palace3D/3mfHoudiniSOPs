= Read3mf =

#type: node
#context: sop
#internal: hdk_read3mf

"""Reads a 3mf file from disk into Houdini geometry."""

== Overview ==

Read3mf unpacks a 3mf archive and imports its geometry, along with
color and texture information where present.

WARNING:
    Multiproperties (a triangle combining several properties at once,
    per the 3mf Materials Specification) are supported, with
    colorgroup, texture, and base material layers and their alphas,
    except for the `multiply` blend method. A multiproperties group
    whose `blendmethods` asks for `multiply` is currently blended with
    the default `mix` instead, and Read3mf puts a warning on the node
    naming the group.

WARNING:
    The Composite Materials extension (`<m:compositematerials>`) is
    not currently supported. A composite materials group that an
    object or triangle refers to directly is skipped, with a warning
    in the console, and whatever refers to it gets the object's
    default color. A composite materials group used as a layer of a
    multiproperties group makes the import fail with an error
    whenever that multiproperties group is used.

WARNING:
    Only the root model file of a 3mf package is currently read.
    Models whose objects live in other model files (the Production
    Extension's `p:path` attribute on components and build items)
    are not supported. The other files are not parsed, and the
    import stops with an error naming the file as soon as it meets a
    component or build item that points into one.

WARNING:
    Read3mf currently understands only the Materials and Production
    extensions. If a file says it requires any other 3mf extension
    (such as Slice or Beam Lattice), Read3mf still reads it, but puts
    a warning on the node naming those extensions. Anything in the
    file that depends on them is ignored, so the result may be
    incomplete or wrong.

WARNING:
    Files written by Save3mf 3.0 or earlier hold Houdini's linear
    colors written as if they were sRGB, so with Convert sRGB on
    they import darker than the originals. The `in_application`
    detail attribute (or the file's Application metadata) shows
    which version wrote a file. Read3mf puts a warning on the node
    when it sees such a file with colors the conversion would
    change. Turn Convert sRGB off and press Read again to
    reproduce the original colors.

== Imported Attributes ==

Read3mf attaches a few attributes to the geometry it produces,
beyond the geometry itself.

Detail attributes, one value per file, read from the 3mf's
`<metadata>` elements when present:
- `in_title`
- `in_description`
- `in_designer`
- `in_application`
- `in_modificationdate`

These mirror the `out_title`, `out_description`, and `out_designer`
detail attributes that [Node:sop/hdk_save3mf] uses. `in_application`
and `in_modificationdate` have no `out_*` counterpart, since
Save3mf sets those itself and doesn't allow overriding them.

Primitive attributes, tagging every primitive with which 3mf
`<object>` it came from:
- `object_id` (integer) — the object's 3mf id. Unique per object,
  per the 3mf spec, even if two objects share the same name (or
  have no name at all).
- `mesh_name` (string) — the object's `name` attribute, if it had
  one, otherwise empty.

NOTE:
    These survive merging multiple objects into one piece of
    geometry (via `<build>` instructions or components), so a file
    with several named objects still lets you tell, per primitive,
    which original object it belongs to.

== Materials and Shaders ==

If the 3mf file has texture or multi-property data (and Only
Geometry is off), Read3mf creates a subnet alongside itself to hold
the materials it builds, named after the node with `_subnet`
appended (e.g. a node named `read3mf1` gets a sibling subnet named
`read3mf1_subnet`). Inside that subnet is a matnet named
`3mf_materials` containing the actual shader(s).

For multiproperties, each layer is laid over the ones beneath it by
its own alpha: a colorgroup color's alpha, or the alpha channel of a
texture image (so a PNG with transparent or partly transparent areas
lets the layers beneath show through there).

NOTE:
    Layers are blended in linear light, as the 3mf Materials
    Specification recommends. Some other applications, including the
    renderer that made the thumbnails in the 3mf Consortium's test
    suites, blend the sRGB values directly instead. Their blends come
    out darker, and a dark layer that is only partly opaque over a
    bright one shows up more strongly in them, so expect blended areas
    to look lighter and smoother in Houdini than in those images.

NOTE:
    The subnet is destroyed and rebuilt fresh every time Read is
    pressed, so re-reading a file doesn't leave stale, duplicate
    shaders behind.

    It is not automatically deleted if you delete the Read3mf node
    itself — this is deliberate, since Houdini doesn't guarantee an
    order for deleting nodes during scene teardown, and destroying
    it from the node's own destructor risked crashes. Delete the
    subnet by hand if you no longer need it.

@parameters

Flip Normals:
    #id: flip
    Flip 3mf normals to match Houdini's winding order, which is
    opposite 3mf's.

Apply Build Instructions:
    #id: build
    Render only the objects listed in the 3mf file's `<build>`
    instructions, applying their transforms. This is how a valid
    3mf file is meant to be assembled. If turned off, the node
    instead renders every object defined in the file's resources,
    regardless of whether it's referenced by a build item — each
    one exactly once, at its own identity transform (its original,
    local placement, ignoring whatever transform a build item would
    have applied). Useful for debugging, or for inspecting resources
    that aren't referenced by any build item at all.

Only Geometry:
    #id: geo
    Import geometry only — skip color and texture information.

Shader Override:
    #id: overrideShader
    Use a single shader for multiple textures on import, recording
    the per-primitive texture assignment in a `material_override`
    attribute rather than assigning a distinct shader per texture.
    Intended to pair with [Node:sop/hdk_save3mf]'s own Uses Shader
    Override option, so a round-tripped part re-exports its texture
    assignments correctly.

Convert sRGB:
    #id: convertSRGB
    Decode the colors in the file from sRGB to Houdini's linear
    `Cd`, so the geometry looks the way the file's colors look in a
    slicer or other application. Applies to colorgroup colors, base
    material colors, and the texture pixels sampled to set the
    default color of a textured object. Alpha is not changed, and
    texture image files are not modified. Multiproperties layers
    are blended after decoding, so the blend happens in linear
    light. Takes effect the next time Read is pressed. Leave this
    on for files from other applications. Turn it off for files
    written by Save3mf 3.0 or earlier, which stored linear values
    unconverted (see the warning at the top of this page).

Debug:
    #id: debug
    Print extra diagnostic information to the console (`std::clog`)
    while reading. Hidden by default, since this is intended for
    development/troubleshooting rather than everyday use.

    NOTE:
        To turn this on, right-click the node and choose Parameters
        and Channels > Edit Parameter Interface. Under Existing
        Parameters, turn on "Show Invisible Parameters" — Debug
        will then appear in that list. Click it, then turn off the
        "Invisible" toggle on its Parameter Description. This makes
        the toggle visible on this one node instance only —
        dropping a new Read3mf node still starts with Debug hidden.

Timer:
    #id: timer
    Report how long the read operation took.

File Name:
    #id: filename
    Path to the 3mf file to read.

Asset Folder:
    #id: assets
    Folder into which the 3mf archive is unpacked (textures and
    other referenced files land here during the read).

Read:
    #id: readBtn
    Triggers the actual read. Read3mf only (re-)imports geometry
    when this button is pressed.

@related
